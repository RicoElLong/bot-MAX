# bot-MAX

MAX-версия сервисного бота [RicoElLong/bot-tech](https://github.com/RicoElLong/bot-tech), перенесённая с коммита `4be15aedcf37da7c26628416879190efa1724b39`.

## Возможности

- Приветствие с исходным фото `assets/welcome.png`.
- Телефон через кнопку MAX «Отправить телефон» или ввод текстом; проверка владельца переданного контакта.
- Описание проблемы и модели стиральной машины, возможность пропустить описание.
- Одна активная заявка на нормализованный телефон: повторная анкета обновляет её.
- Выбор даты на ближайшие 7 дней и свободного времени **08:00–22:00 с шагом 2 часа, Europe/Samara (UTC+4)**. Прошедшее время скрыто; один слот нельзя занять дважды.
- Меню «Поломка», «Запись», «Контакты», «Отзывы».
- Уведомления администраторам о входах, заявках и записи.
- `/admin`: статистика, история входов, заявки с телефонами, перелистывание, удаление с подтверждением и освобождением слота.
- SQLite сохраняет заявки, этап анкеты и занятые слоты между перезапусками.

Тексты, фото, логика анкеты, расписание и хранилище перенесены из исходного бота. Сетевой слой заменён на MAX Bot API; Telegram SDK не используется. В MAX меню находится в кнопках под сообщениями. Сайт и его отдельный HTTP API из bot-tech в этот репозиторий не перенесены.

## Запуск

Нужен Python 3.10+ (проверено на Python 3.12). На Linux должна быть установлена системная база часовых поясов, на Windows `tzdata` устанавливается из requirements.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env.local
```

Заполните `.env.local` локально:

```dotenv
BOT_TOKEN=токен_бота_MAX
ADMIN_IDS=ваш_числовой_MAX_ID
```

Токен выдаётся для бота MAX; токен Telegram не подходит. `.env.local` исключён из Git. Не переносите `.env` и клиентскую базу Telegram-бота: MAX имеет собственные ID пользователей. Тексты контактов и отзывов настройте через `CONTACTS_TEXT`, `REVIEWS_TEXT`, `REVIEWS_URL` в `.env.local`; имена кнопок — через `BUTTON_*` из примера.

Если свой MAX ID пока неизвестен, временно оставьте `ADMIN_IDS` пустым, запустите бот, отправьте ему `/myid`, внесите полученный ID и перезапустите процесс. Администратор должен первым открыть личный диалог с ботом, чтобы получать уведомления.

```sh
.venv/bin/python bot.py
```

Команды: `/start`, `/myid`, `/admin`, `/cancel`. Бот обрабатывает только личные диалоги. Запускайте один процесс на токен и базу. Используется long polling, публичный сервер и webhook не нужны. Если у токена уже есть webhook-подписки, запуск остановится с объяснением; удалите их через MAX API перед переходом на polling.

Без токена запуск завершается сообщением `Укажите BOT_TOKEN в .env.local`. База по умолчанию — `data/bot.sqlite3`; сохраняйте и резервируйте каталог `data`. Для остановки используйте Ctrl+C.

По умолчанию API: `https://platform-api2.max.ru`, как в официальном [SDK MAX](https://github.com/max-messenger/max-bot-api-client-ts), коммит `a5c40a09eed306405419ad2232e6b90466dd74d6`. При необходимости адрес можно задать через `MAX_API_URL` (только HTTPS). При ограниченной сети разрешите этот API-хост и HTTPS-хост загрузки фото, который API возвращает из `/uploads`. Токен передаётся только API в заголовке Authorization, а не серверу загрузки файла.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

26 тестов: исходные сценарии анкеты, уникальность заявок и слотов, перезапуск SQLite, права администратора и удаление, а также события, контакты, кнопки и HTTP-запросы MAX. HTTP в тестах подменён: они не используют токен и не отправляют реальные сообщения.

После добавления токена проверьте в MAX: `/start` → фото → свой контакт → описание → «Далее» → дата → время → меню; затем с администраторского аккаунта `/admin` → заявки → удаление с подтверждением. Проверьте уведомления и повторную доступность освобождённого времени. До этой проверки совместимость с реальным ботом не считается подтверждённой.
